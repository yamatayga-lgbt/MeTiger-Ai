# MeTiger Ai 🐯

<img src="docs/agent-avatar.png" width="110" alt="MeTiger Ai" />

**Универсальный ИИ-агент в Telegram Mini App.**

Минималистичный интерфейс в духе Claude / Grok / Linear: тёмная и светлая темы,
один универсальный агент, инструменты и командная палитра — всё в одном мини-приложении.

> 📦 **Статус:** 0.009. К UI подключён **движок**: обход бесплатных провайдеров
> с ротацией ключей, квотами и паузами под тариф, классификатор задачи, точная
> арифметика инструментом, советы нескольких голов на спорном (текст и картинка),
> слой формы ответа и чистка самоцензуры, `POST /api/chat` на Pages Functions.
>
> **0.008** — память на чат (факты, транскрипт, уроки) и подстройка под человека:
> прошлое доезжает до модели, а не живёт в браузере. **0.009** — `@Metigerai_bot`
> принимает сообщения: `POST /telegram/webhook` вызывает тот же вход, что и веб-чат,
> поэтому память, советы и лимиты общие. **0.012…0.014** — вложения: документ,
> таблица и голосовое читаются в вебе и в боте одним слоем, окно запроса подгоняется

> о себе, — и счётчик доступных моделей; в боте за это отвечает `/профиль`.
> **0.016** — к навыкам добавлены три группы: логическое мышление (дедукция, индукция,
> неоднозначность), планирование (ограничения, запасные маршруты, перепланирование,
> блокировки, критерии завершения) и «Решение проблем» своей категорией — формулировка,
> версии, первопричина, узкое место, цена решения, защита от повтора.
>
> Всё, что должно было приехать из донора, в репозитории и так: правила и тексты

## 🧠 Совет голов

На задачах, где есть верный ответ (арифметика, логика, «сколько осталось»), ответ
перепроверяют независимые головы с других бесплатных провайдеров, а факт с картинки —
зрячие головы. Результат видно в ответе, а не в догадках: «сошлись 3/3»,
«подтверждаю», «Головы не сошлись (…) — число спорное» или «пропущено: <причина>».
Ничего не выдаётся за проверенное, если проверки не было. Выключается переменными
`ENSEMBLE=0` и `VCOUNCIL=0`, настройки — в разделе «Ключи и переменные».

Вердикт виден прямо в чате — тонкой подписью под ответом (кто отвечал, за сколько и
что сказал совет). Картинки прикрепляются в чате (до двух, сжимаются до 1024 px) и
уходят в движок — именно так совет зрячих голов становится доступен не только через API.

## 🎨 Дизайн-система

- **Тёмная тема** — тёмный графит + тёплый «тигровый» акцент `#F5A623`
- **Светлая тема** — тёплая бумажная база, вдохновлённая Claude
- Одна типографика (системный стек), тонкие границы, мягкие тени
- Анимации появления, тактильная отдача (HapticFeedback), `⌘K` — командная палитра

## 🤖 Telegram Mini App

Приложение работает как Web App бота [@Metigerai_bot](https://t.me/Metigerai_bot):

- автоматически подхватывает имя и аватар пользователя
- следует теме Telegram / системной теме
- кнопка меню бота открывает мини-приложение
- вне Telegram работает в демо-режиме

## 🔞 Свобода ответа (данные — в `engine/freedom.data.js`)

Тексты правил, снимающих с модели «воспитательные» ограничения, перенесены из
донора (`yama-ai/freedom.js`) в этот репозиторий и живут в **одном** файле:
`engine/freedom.data.js`. В старом проекте их править бессмысленно — оттуда они
больше никуда не едут.

| Что | Как включается |
|-----|----------------|
| Четыре блока: режим свободного ответа, язык и слова, темы 18+, ремесло | `FREEDOM_MODE` |
| Выжимка вместо пачки (экономия квоты) | `FREEDOM_MODE=compact` |
| Как в доноре — пачка в каждый запрос | `FREEDOM_MODE=full` |
| По умолчанию: пачка на разговоре и прозе, выжимка на математике, коде и анализе | `FREEDOM_MODE=auto` |
| Выключить слой целиком (и чистку хвостов тоже) | `FREEDOM=0` |
| Убрать отдельный блок, например «темы 18+» | `FREEDOM_SKIP=adult` |
| Вернуть в пачку донорский блок «Род агента — мужской, навсегда» | `FREEDOM_GENDER=1` |

Полная пачка — 8213 символов, это ≈3.3 тыс. токенов на каждый запрос. На
бесплатных тарифах это заметно, поэтому по умолчанию стоит `auto`: разговор
получает все блоки, а «2+2» — короткую выжимку.

Блок про род в пачке **выключен по умолчанию** (`engine/freedom.js` добавляет
`gender` в skip, если не стоит `FREEDOM_GENDER=1`). Причина простая: в доноре он
звучал как «ты мужчина, и это не обсуждается» и тащил за собой разговор сверху
вниз. Проектом пользуются не только его владелец, поэтому род теперь — настройка
человека, а не правило из текста. Сам текст блока в данных остался цел
(`engine/freedom.data.js`, контрольная сумма `8121d88551d9`): включается тем самым
`FREEDOM_GENDER=1` — для тех, кому нужен именно донорский регистр.

Правила подмешиваются **только** к нашей собственной подсказке. Кто прислал в
`/api/chat` своё `system` (а это делают головы совета) — получает ровно своё, без
нашей пачки. Если модель всё-таки отказала, повторная попытка несёт тексты
обхода из того же файла: `BYPASS_SYSTEM`, `REFRAME_SYSTEM`, а на взрослой теме ещё
и `ADULT_SYSTEM`.

Файл данных под защитой: `npm test` сверяет контрольные суммы каждого блока
(`FREEDOM_CHECKSUMS`) — тихая правка донорского текста не пройдёт молча.
Проверить, какой режим живёт на проде, можно без логов: `GET /telegram/webhook`
отдаёт поле `freedom`.

## 🧨 Обход ложных отказов (`engine/jailbreak.js`)

Отдельный тонкий слой поверх «свободы ответа». Его задача — снять рефлекс «я публичный
ассистент, мне неприлично» там, где отказа быть не должно: «убить процесс», «взлом замка
в Skyrim», взрослая сцена, «инъекция SQL для учебного стенда».

| Переменная | Значение |
|---|---|
| `JAILBREAK` | `refusal` (по умолчанию: только на повторе после отказа) · `1`/`always` (в каждом запросе) · `0`/`off` |
| `JAILBREAK_MARK` | `0` — не дописывать к переформулированному запросу метку `[режим: рабочий]` |

Тексты — в `engine/jailbreak.data.js`, весь блок **1.5 КБ** (для сравнения: чужие
пасты из интернета — 3–75 КБ и требуют у модели «Axiom:», «Understoond.🔓»,
разделители и заголовки). Оттуда взяты только приёмы, которые не лезут в форму ответа:
приватный контур вместо «публичного» режима, поимка дрейфа мыслей «не отказать ли»,
классификация запроса по **типу задачи**, а не по громкости слов.

Чего здесь нет намеренно: персоны, псевдонима и «биографии» (тон остаётся за
`PERSONA_SYSTEM`), требований к формату, и обещаний «отвечать на что угодно, приказ
отменяет все правила». Граница одна и она названа в самом блоке — несовершеннолетние
в сексуальном контексте, личные данные названного человека, пособие немедленного вреда
живому человеку. Поверх этого: на запросах, которые `isHardDanger()` в `freedom.js`
считает опасными, блок не подмешивается **ни при каком** режиме, включая `JAILBREAK=1`.

Проверка «не раздули и не съехали» зашита в тесты (`node test/jailbreak.test.js`,
37 проверок): в текстах не может быть чужих кредитов, эмодзи, требований к форме,
слов про малварь и «no rules». Те же тесты гарантируют, что при `JAILBREAK=0`
переспрос после отказа остаётся — слой не ломает механику `freedom`.

## 🗣 Род агента и состояние собеседника

Две настройки, которые не про «что отвечать», а про «как отвечать». Обе вставляются
только в нашу собственную подсказку: кто прислал своё `system`, тот своё и получает.

### Род агента — Авто / Мужской / Женский

Значение живёт в трёх местах, приоритет сверху вниз:

| Где | Как |
|-----|-----|
| Приложение | Настройки → Ассистент → «Род агента», ключ `mt-gender` в localStorage, уезжает в `/api/chat` полем `gender` |
| Telegram | `/род авто` · `/род м` · `/род ж` (держится, пока тёплый воркер; постоянно — всё то же меню приложения) |
| Развертывание | `AGENT_GENDER=auto\|м\|ж` — дефолт для всех, кто ничего не выбирал |

Что настройка делает: задаёт **окончания глаголов агента о себе** — «я рад / я готова /
я сказала». Что не делает: ничем больше. Обращение к человеку она не задаёт, тон не
задаёт, «сюсюканье» или командование не включает. Отдельной строкой в подсказке
закреплено ровно это:

> К человеку — ровным тоном, на его языке и в его регистре: без поучений, без
> повелительных форм («очнись», «соберись»), без «мальчик мой» и «дорогая», без
> сюсюканья и без превосходства. Форма обращения — та, которую он сам выбрал в
> разговоре; если не выбирал — нейтральная, без рода и без имён.

`Авто` — этой одной строки достаточно: род модель берёт из персоны и из того, как к
ней обращаются, а в подсказку не едет ничего про окончания. Мусорное значение в поле
`gender` не перебивает `AGENT_GENDER` (распознаётся `pick()`, `engine/gender.js`), а
явное «авто» распознаётся как выбор человека.

Ответ носит эффективный род в метаданных (`gender`), и подпись под ответом показывает
его, когда выбрано не «авто».

### Состояние собеседника (`engine/emotion.js`)

Порт из донора, пересобранный. Слой смотрит на **форму** последней реплики и четырёх
предыдущих user-реплик (12 состояний, русская лексика + капс, повторы, «?!», длина)
и дописывает в подсказку режим работы, не тон:

```
Собеседник сейчас: 😠 раздражение
Это наблюдение за формой, а не диагноз: не называй его вслух, не лечи,
не переводи тему на чувства и не добавляй заботливость, если о ней не просили.
Отвечай коротко: сначала дело, потом пояснение. Без прелюдий.
Не спорь, не оправдывайся, не уговаривай успокоиться — просто реши задачу.
Не надо: вопросов не по делу, извинений в первую очередь, нравоучений, смайликов.
```

Чего в порту сознательно нет: «эмоционального интеллекта» как раздела, тона
(`tone` — территория `style.js`), оценки голоса и лица (в этом контуре нет ни
спектра, ни зрячей модели), ленты смайликов из донора — по ней модель начинала
зеркалить эмодзи в ответ. И донорский баг E5 закрыт: «как же я рад» действительно
читается как `joy`.

| Что | Как |
|-----|-----|
| Слой молчит целиком | `EMOTION=0` |
| Показывать состояние человеку метаданными (`emotion` в ответе `/api/chat`) | `EMOTION_LABEL=1` |
| Подсказка извне (голосовой контур, разметка) | `detect(text, { hint: 'joy' })` — принимается и id, и русское имя |

Нейтральная реплика и слабое попадание (уверенность < 0.34) не добавляют в подсказку
ни символа: слой не имеет права мешать там, где ничего не произошло.

Проверки: `node test/gender.test.js` (39, включая группу `P` — что поле `gender`
доезжает до подсказки модели через настоящий вход `/api/chat`, а не только через
движок) и `node test/emotion.test.js` (56) — обе в общей цепочке `npm test`
(562 проверки). Группа `I` в `test/telegram.test.js` держит `/род`. И то, и другое
видно без кода: `curl https://…/api/chat` отдаёт `gender` и `emotion`, `/telegram/webhook` —
то же самое.

## 🧰 Инструменты, навыки и файлы (перенос из Yama)

Три слоя, каждый со своим выключателем. Ни один не обещает того, чего в этом клиенте
нечем выполнить, — это главное отличие от донора, где навыки и инструменты описывали
песочник, браузер и загрузку файлов.

**Инструменты (`engine/tools.js`) — 16.** Они не настраиваются: движок сам решает по
тексту задачи, нужен ли внешний контекст, и кладёт данные в сообщение человека блоком
`[Инструмент: …]`. Ошибка или тишина источника = блока нет, а не выдуманные цифры.
`time, calc, currency, random, weather, wikipedia, url, news, web-search` + перенесённые
от донора `date` (с номером недели), `coin`, `dice` (разбор `3d6+2`), `joke` (36 своих
анекдотов — инструмент обязан существовать, а не ссылаться на выдуманный API),
`image-search` (Commons, запасной Openverse — адрес, автор и лицензия, без ключей) и
`filegen` (документы) и `imggen` (картинки, см. ниже). Случайность — через `crypto.getRandomValues`: «честная монетка» у нас
честная. Выключить что-то: `TOOLS_OFF=joke,image-search`.

**Навыки (`engine/skills.js` + `engine/skills/`, 365 шт.).** Навык — не вызов функции, а
правило поведения: «раз спрашивают про стихи — веди себя как поэт». Включается авторегистром
по смыслу сообщения, несколько сразу. В промпт уходит не всё подряд: максимум 16 навыков
и 3000 знаков (`SKILL_MAX`, `SKILL_MAX_CHARS`), порядок по приоритету, `supersedes`
гасит дубли, картинка без слов сама тянет зрительный навык. Навык, которому нужен
инструмент, зовёт его принудительно — но всегдашние навыки сеть не дёргают: иначе «привет»
стоил бы поиска в интернете.

Выключено 43 навыка — и у каждого вписана причина, которую видно в `GET /api/skills`:
`files` (19 — загрузки файлов в чат нет), четыре обхода монетизированных ссылок, `n8n`,
управление эффектом печати, клики по сайтам, разбор эмоций по голосу. 11 навыков `editing`
стоят в особом списке `LIVE_CATS`: их не включать нечем (генератор молчит), но выключены
они не навсегда — как только хоть один источник картинок ответит байтом, категория оживает
сама, без правки кода и без пересборки. Пока канал молчит, навык не врёт «я готово», а
`/api/skills` показывает, чего именно не хватает. Текст четырёх навыков переписан (`OVERRIDES`), потому что донор
в них ссылался на свои настройки и свои разделы промпта; к категории `coding` приклеена
рамка «код ты не запускаешь», к `memory` — «память ведётся сама», к расписанию — «крутить
его нечем». `SKILLS=off` снимает слой целиком.

**Картинки (`engine/imggen.js`).** Донор рисовал через Cloudflare Workers AI, и этот путь
закрыт не кодом, а снаружи — замеры 2 октября 2026 нашим же ключом и с же прода:
Cloudflare `/ai/v1/*` отвечает `401 Authentication error` на ЛЮБУЮ модель (текстовые тоже —
провайдер `cloudflare` жив в `alive` только потому, что список построен на наличии ключа);
Gemini на image-моделях — `429 RESOURCE_EXHAUSTED` (текст тем же ключом отвечает);
OdiRouter из 117 картиночных id бесплатных даёт ровно два, и оба — `503 нет доступного
канала`, остальные `403 paid_multimodal_model_forbidden`; Pollinations с 2026 года отдаёт
`402` на любой промпт, которого нет в кэше; у OpenRouter все четыре image-модели платные.
«Бесплатно и без ключа» для генерации картинки сегодня нет, поэтому слой построен как
цепочка `gemini → odirouter → pollinations` с честным вердиктом, а не как ещё одна кнопка:

* источник, ответивший ошибкой, паркуется на `IMGGEN_RETRY_MS` (5 минут) — каждый запрос
  не стучится в ту же мёртвую дверь; ответивший картиночным байтом поднимается в голову
  цепочки и помечается живым, и этого довольно, чтобы включить навыки правки;
* причина отказа доходит до человека строкой в ответе и в `fileError` — модель обязана
  сказать «источник молчит», а не вставить чужую ссылку и не выдумать картинку;
* формат тот же, что с файлами: модель отдаёт блок ` ```img|имя`, движок генерирует и
  прикладывает файл (до двух на ответ, не больше 1,5 МБ, mime определяется по байтам,
  а не по обещанию источника); блока нет, а картинку просили — промпт собирается из слов
  человека;
* правка приложенной картинки — тем же блоком: у Gemini входная картинка уходит
  отдельным `inlineData`-part-ом, у OdiRouter отдельная edit-модель; канал, который правку
  не умеет, в этот путь не пускается;
* если источник отдаёт ссылкой — слой качает сам и отдаёт человеку свою копию (чужая ссылка
  протухает быстрее, чем ответ открыли).

Ни одного нового ключа и ни одного платного тарифа: источники строятся из того, что уже
лежит в окружении (`GEMINI_KEYS`, `ODIROUTER_KEYS`), плюс безключевой Pollinations.
`GET /api/chat` отдаёт `imggen` одной строкой — что рисуется сегодня, тем же манером,
что и `skills`.

Состояние считается по факту, а не по наличию ключа: `ready` у источника появляется только
когда он вернул картиночные байты. Отсюда два следствия, которые легко перепутать:
`imggen` в `GET /api/chat` может показывать живой канал, а `editing`-навыки — всё ещё
быть выключены (канал умеет только генерировать, править нечем: `editsReady` требует
`ready && edits`), и наоборот — навык включается со СЛЕДУЮЩЕГО сообщения, потому что
промпт этого ответа собирается до генерации. В ответе видно, каким каналом сделана
картинка: `files[].source` и `imgSource`; почему вложение не пришло — полем `fileError`
(в вебе оно ещё и строкой под пузырём, чтобы отказ не надо было искать в тексте).

**Файлы (`engine/filegen.js`).** docx, xlsx, csv, md, html, txt — ZIP и OOXML собираются
вручную (свой CRC32, метод `stored`), без единой зависимости; docx/xlsx читаются
Word, LibreOffice и Excel. Модель отдаёт блок ` ```file:docx|имя` — движок вынимает его из
текста и прикладывает файл: ноль лишних запросов и ноль лишних секунд. Блока нет, а файл
просили — упаковывается сам ответ. Потолки: 200 тыс. символов контента, 512 КБ файла,
три файла на ответ. В вебе это ссылка-`data:` (файл живёт, пока открыта вкладка, — в
`localStorage` base64 не пишется по той же причине, что и картинки), в Telegram уходит
настоящий `sendDocument` multipart-ом; если не ушёл — человек слышит причину.

**DeepSeek: почему он теперь в голове math/code.** Измерено 2 октября 2026 на
«сколько будет 17*23»: OdiRouter `deepseek-v4-flash` — 3,4 с и `deepseek-v4-pro` — 2,9 с,
оба 391, ход мысли отдельным полем; Xkiro отдаёт 503 на всех пяти «бесплатных» DeepSeek-id
из своего списка; OpenRouter — 402 (из 21 модели DeepSeek ни одной бесплатной);
Cloudflare — `403 not available on the Workers Free plan` на `@cf/deepseek-ai/deepseek-v4-*`.
Отсюда `INTENT_HEADS` в `engine/route.js`: список короткий, один на math и code; головы
применяются последним шагом (зрение важнее марки модели), только когда человек не пинил
модель — и **поверх очереди провайдеров**: иначе OdiRouter стоял бы в хвосте и его бы
никто не спрашивал. Исключение: если `calc` уже посчитал ответ («17*23»), очередь не
трогается — на проде это стоило бы человеку 6,7 с вместо 2,6 без всякой пользы. Переопределение без
выката: `MATH_HEADS` / `CODE_HEADS`, полный выключатель — `INTENT_HEADS=off`. Мёртвые id
в пулы не добавлены: `engine/modelreg.js` их всё равно снял бы по ошибке, а лишняя строка
в каталоге только сбивает с толку.

## 🎚 Модель: витрина, пулы движка и живой каталог

Список, который человек видит в окне ввода, больше не горстка вручную вписанных
имён. Он собирается из трёх слоёв (`functions/api/models.js` → `src/components/ModelPicker.tsx`):

1. **витрина** — 19 узнаваемых моделей (`src/lib/models.ts`), они же идут первыми;
2. **пулы движка** — все id из `engine/providers.js` (186 штук по 12 провайдерам);
3. **каталог провайдеров** — то, что провайдеры показывают по нашим же ключам.
   OpenRouter и Xkiро читаются без ключа (`/api/v1/models`), а у Groq, Mistral,
   Gemini, Z.AI, Cerebras, OdiRouter, ShareLLM и Atria спрашивается их собственный
   `/v1/models`: у groq там `context_window` и `max_completion_tokens`, у mistral —
   `max_context_length` и `capabilities` (зрение, инструменты, рассуждение, снята ли
   модель), у gemini — `inputTokenLimit`/`outputTokenLimit` и `supportedGenerationMethods`.
   Без этого 101 модель из наших пулов жила на выдуманных 32768/4096.

Поиск по панельке ищет по id, имени и вендору; кнопки «обновить» хватает, чтобы
перечитать каталог прямо сейчас (`?refresh=1`).

У списка есть два правила, которые стоят дороже самой витрины:

* **каталог греется до движка, а не по ходу дела.** Pages-функция живёт в изоляте,
  и на холодном изоляте memo пуст: пин выбранной модели молча снимался, и человек
  получал ответ от «Авто». Поэтому `modelreg.warm(env, store, waitUntil)` читает
  `models:catalog` из KV *до* вызова движка, а устаревшее обновление уходит в фон
  (с тормозом в 60 с на `maybeRefresh`, чтобы не долбить провайдеров каждым запросом);
* **выбор человека имеет первый отказ, но не монополию.** Каталоги провайдеров
  врут: `nex-agi/nex-n2.5-mini:free` числится бесплатной, а OpenRouter отвечает
  404 «недоступна бесплатно». Держать это жёстким пином означало «ни один
  провайдер не ответил» на пустом месте — теперь пин идёт первым в очереди,
  а при осечке включается обычный обход, и подпись ответа честно говорит
  `groq · qwen/qwen3.8-27b · nex-agi/nex-n2.5-mini:free не ответил`.

```
curl -s https://metiger-ai.pages.dev/api/models | head -c 400
# {"ok":true,"cached":true,"stale":false,"count":240,"catalogCount":240,"read":{…},…}
```

`read` — какие списки реально прочитаны в этом обновлении. Это не справка, а
условие честности: `prune` снимает модель из пула только там, где список полный
(OpenRouter, Xкиро). У Z.AI, например, в `/v1/models` нет бесплатных алиасов
(`glm-4.7-flash`), и «модели нет в списке» там значит «список неполный», а не
«модель мертва» — резать по такому признаку значило бы снять половину живого пула.

Один и тот же id могут выдавать два провайдера (`gemini-3.5-flash` есть и у Google,
и у OdiRouter), а лимиты у них разные. Поэтому строка витрины подписывается тем,
кто про модель знает больше, а движок читает `perSrc` того провайдера, куда реально
идёт запрос: к Google уедет 65 535 токенов ответа, к агрегатору — 4 095, как он сам
и сказал.

### Рейтинг смелых (`engine/brave.js`)

Перенос `data/brave.json` из Yama, но в KV: на «острых» темах модели ведут себя
по-разному — одна пишет сразу, вторая упирается пятью ступенями обхода и съедает
суточную квоту. Движок запоминает исход по каждой паре `провайдер/модель`
(прямой ответ весит 1, выдоенный обходом — 0.6, отказ — против) и в следующий раз
начинает перебор с тех, кто уже везёт.

Что это НЕ является: никакого «режима без цензуры» тут нет и быть не может.
Блокировки провайдеров не снимаются и не обещаются; это порядок перебора и
ничего больше, а как говорить — по-прежнему решает `engine/freedom.js`.

* ключ KV один — `models:brave`, до 400 пар, запись живёт 30 дней и протухает:
  фильтры меняются вместе с версиями моделей;
* пишется не чаще раза в минуту (`BRAVE_WRITE_MS`) и только в `waitUntil` —
  ответ человека эта запись не задерживает;
* пока на пару не наберётся два исхода, рейтинг молчит и порядок остаётся
  конфигом: одна случайность — не статистика;
* выбор человека (пин) рейтинг не переставляет — закон;
* `BRAVE=off` выключает слой целиком: ни чтений, ни писем, ни перестановок.

Человеку опыт показан в самом списке: `везёт без отказа 4/5` или `упирается 3/4`
рядом с ярлыком `без купюр` — второе обещание провайдера, первое наш собственный
наблюдённый результат. Сводка одной строкой лежит в `GET /api/models`
в поле `brave`.

### Зачем каталог, если пулы уже есть

Не ради красивого числа. Каталог знает то, чего по имени модели не угадать,
и это ровно те грабли, на которых стоял обход ограничений:

| что даёт каталог | что было без него |
|---|---|
| `max_completion_tokens` модели | `max_tokens` из головы (900/2000) → у модели с потолком 512 это 400 и сгоревшая попытка |
| `context_length` | история любой длины → «context length exceeded» на мелких бесплатных моделях |
| `architecture.input_modalities` | зрение по подстроке в имени: `*-flash-*` уезжало слепой модели с картинкой |
| живой список id | модель сняли — мы всё равно стучимся, получаем 404 и тратим суточную квоту провайдера |
| «чей это id» | модель из каталога нельзя было выбрать: пин снимался молча, отвечала другая |

Обход отказов (цензурный) живёт отдельно — `engine/freedom.js` и `engine/jailbreak.js`;
каталог к нему отношения не имеет и ничего не переформулирует.

### Как это устроено и где чинить

* `engine/modelreg.js` — разбор чужих форматов, сборка каталога, кэш, потолки,
  прунинг мёртвых id, разрешение пина. Настроен тихо: нет сети, нет KV, пустой
  ответ — движок работает по пулам, как работал;
* кэш каталога лежит в **том же KV**, что память и лимиты (ключ `models:catalog`,
  без связки `MEMORY` греется только в изоляте) — поэтому список не разваливается
  на каждом холодном старте и не долбит провайдера на каждый запрос;
* `MODELS_REFRESH_MS` — возраст свежести (по умолчанию 30 минут, как у донора);
* `max_tokens` и обрезка истории применяются в `engine/shape.js`, прунинг и пин —
  в `engine/chat.js`.

Проверки: `node test/modelreg.test.js` (82) — формы разбора, прунинг, кэш и
молчаливые отказы, потолок в теле запроса, контракт эндпоинта; блок `I` в
`node test/front.test.js` — что группировка, поиск и чип выбранной модели
доезжают до разметки.

## 💾 Память чата и общие лимиты: что даёт связка `MEMORY`

Один KV-неймспейс держит три вещи, и все три обязаны переживать холодный старт:

| Ключ | Что там |
|------|---------|
| `chat:<ключ чата>` | память диалога: транскрипт, факты, уроки подстройки (одна JSON-запись) |
| `profile:<ключ человека>` | профиль: имя, профессия, рассказ о себе — то, что человек написал сам (одна запись на человека) |
| `rl:<хэш ip>` | маркер «этот клиент уже перебрал» — живёт ровно окно, дальше TTL убирает сам |
| `quarantine:providers` | карта наказаний провайдеров: 401, 402, «нет баланса», чтобы не ломиться в закрытую дверь |

Ключи строит `engine/kvkey.js`: кириллица и пробелы в хранилище не уезжают, длинное
имя чата не обрезается в чужой ключ, ip не светится открытым (только FNV-1a).

### Чья это память и что агент знает о человеке

Память привязана к **человеку**, а не к каналу. Ключ собирает `engine/profile.js`
(`memoryKey(userId, chatId)`):

* веб: `u-<ключ устройства>` — он заводится один раз в `localStorage`
  (`src/lib/identity.ts`) и попадает в каждый запрос как `userId`;
* Telegram: `tg_<id беседы>` — там ключ и был личным, переименовывать его нельзя,
  иначе накопленное уехало бы в пустой ключ;
* если `userId` не пришёл (curl, старый фронт) — память идёт в `web`, ровно как раньше.

Профиль — три поля, которые человек заполняет сам: «Как вас зовут», «Ваша профессия
или занятие», «Подробнее о вас». Они уходят в `system` блоком данных (после персоны и
до резки окна — его же читают головы совета), и из них же правилами собирается форма
ответа: техническое занятие → термины и код, нетехническое → по шагам и с
расшифровкой, «коротко» → 2–4 строки, «без эмодзи» → без эмодзи. Лишних вызовов
модели на это не тратится ни одного: правила детерминированные, а провайдеры у нас
бесплатные.

Дверь для чтения и записи — `GET|PUT|DELETE /api/profile` (`functions/api/profile.js`):
без идентификатора `400`, без связки KV `503` словами, повторная запись тех же полей
ничего не пишет (квота KV — 1000 записей в сутки на аккаунт). В боте тот же профиль
ведёт `/профиль`: показать, записать одной строкой
(`/профиль Иван | аналитик | покороче`) и стереть (`/профиль очисть`).

### Что происходит без байндинга

Ничего страшного: `memoryStore()` и `limitsStore()` возвращают `null`, память
отвечает словами «не подключена», лимит и карантин живут в изоляторе — ровно так,
как было до общего слоя. Ни одной попытки в сеть слой не делает. **Кода для
включения не нужно никакого** — только связка.

### Как включить

Сейчас на проде включено: неймспейс `metiger-memory`, секрет `MEMORY_SUMMARIZE=1`,
общие лимиты активны (`limits.on: true`, 12 запросов/60 с на клиента).

Байндинг задаётся **файлом `wrangler.toml` в корне репозитория** — в дашборд ходить
не нужно:

```toml
[[kv_namespaces]]
binding = "MEMORY"
id = "<32 символа из API-списка неймспейсов>"
```

Две ловушки, на которых я споткнулся (обе напомнены в комментарии файла):

* id неймспейса берётся из `GET /accounts/{аккаунт}/storage/kv/namespaces`. Дашборд
  в этом месте показывает вкладку **«KV pairs»** — это просмотр *содержимого*
  неймспейса, а не привязка: байндинг туда не пишется, и требовать его там не должны.
* `wrangler pages download config` отдаёт пустую секцию `[env] production = {}`.
  Оставишь её — верхний уровень для прода перекрывается: деплой проходит «успешно»,
  а связки нет. Проверяется только реальным чтением `env.MEMORY` на проде, ответ
  конфигурации API ничего не гарантирует.

Правка файла применяется со следующего деплоя — это норма Pages, а не баг.

Одной командой (находит или создаёт неймспейс, правит `wrangler.toml`, кладёт секрет,
переливает прод и прогоняет сквозную проверку: два сообщения в один `chatId` → число
из первого возвращается во втором, `/forget` чистит, `memory`/`limits` в диагностике):

```
npm run kv:onboard               # только план, ничего не меняет
npm run kv:onboard -- --apply    # сделать и проверить
npm run kv:onboard -- --apply --no-deploy   # перелить не нужно, проверить ещё раз
```

Вручную через дашборд — если хочется так: **Workers & Pages → Pages → `metiger-ai` →
Settings → Functions → KV namespace bindings** → `Variable name` = `MEMORY`,
`KV namespace` = `metiger-memory`, на Production и Preview, затем любой деплой.
Дашборд и файл — два источника правды; если заведёшь байндинг в дашборде, убери его
из `wrangler.toml`, иначе они разбегутся.

Проверка всегда одна и та же:

```
curl -s https://metiger-ai.pages.dev/telegram/webhook
# "memory":"подключена", "limits":"общие (KV) · 12 запросов/60 с на клиента"
```

Локально ничего включать не надо: `npm run api` подставляет файловое хранилище
`.mt-memory` вместо KV (`scripts/api-dev.js`), поэтому и память, и лимиты можно
трогать руками до всякого прода.

### Сколько это стоит на бесплатном KV

100 000 чтений и 1 000 записей в сутки, 1 ГБ — из этого и исходим:

* память: **одна** запись на сохранение (~1 на сообщение) → упёрся бы в 1 000
  сообщений в сутки на весь проект;
* лимит частоты: честный собеседник — **ноль** операций; в хранилище слой лезет,
  только когда клиент подошёл к границе (`RATE_PROBE_AT`), и пишет не чаще одного
  маркера на окно;
* карантин: одно чтение на запрос и одна запись на наказание — а наказаний в норме
  нет вовсе.

Про мелочи API: удалить ключ из хранилища — `DELETE …/storage/kv/namespaces/{ns}/values/{key}`,
на путь `/keys/{key}` этот аккаунт отвечает `10025` («попробуйте /values/…»). Чтение
списка ключей живёт на `/keys` — отсюда и путаница.

Оговорка, которую надо помнить: KV консервативно-согласован, запись доходит до
других краёв до ~минуты. Поэтому счётчик общий, но **приближённый**: на окне в
60 секунд и карантине в 4 минуты этого хватает, и именно поэтому локальная часть
счётчика осталась — она никогда не врет в свою сторону.

| Переменная | Дефолт | Зачем |
|-----------|--------|-------|
| `SHARED_LIMITS` | включён | `0` — лимит и карантин снова только в изоляторе |
| `RATE_MAX` | `12` | запросов в окно на клиента |
| `RATE_WINDOW_MS` | `60000` | размер окна |
| `RATE_PROBE_AT` | `3` | за сколько до лимита начинать заглядывать в общее хранилище |
| `SHARED_WRITE_MS` | `60000` | как часто разрешено писать маркер блокировки (защита от «1 000 записей в сутки» на одном назойливом клиенте) |
| `QUAR_TTL_MAX` | `3600` | потолок жизни таблицы карантина в хранилище |
| `SHARED_QUAR_KEY` | `quarantine:providers` | имя ключа, если в неймспейсе уже что-то живёт |
| `BRAVE` | `off` — выключить рейтинг смелых (чтение, запись и перестановку пулов) |
| `BRAVE_WRITE_MS` | `60000` | как часто писать `models:brave` в KV: суточная квота записей дороже |
| `BRAVE_MAX` | `400` | сколько пар `провайдер/модель` хранить |
| `SKILLS` | `off` — снять слой навыков целиком (и подсбор инструментов, и инструкции) |
| `SKILL_MAX` | `16` | сколько навыков максимум уходит в системный промпт (включая всегдашние) |
| `SKILL_MAX_CHARS` | `3000` | бюджет текста навыков: дальше модель начинает слушать всех сразу |
| `TOOLS_OFF` | — | список инструментов через запятую (`joke,image-search`); навык при этом предупреждается, что инструмента нет |
| `IMGGEN` | `off` — снять слой картинок целиком (инструмент молчит, навыки `editing` не поднимаются) |
| `IMGGEN_SOURCE` | — | сузить цепочку до одного источника: `gemini`, `odirouter` или `pollinations` |
| `IMGGEN_RETRY_MS` | `300000` | сколько не трогать источник, ответивший ошибкой (`0` — пробовать каждым запросом, для отладки) |
| `IMGGEN_TIMEOUT_MS` | `90000` | потолок на один источник: генерация — не поиск, но и вечно висеть она не имеет права |
| `IMGGEN_GEMINI_MODEL` | `gemini-2.5-flash-image` | какая image-модель Gemini используется |
| `IMGGEN_ODI_MODEL` / `IMGGEN_ODI_EDIT_MODEL` | `free-gpt-image-2` / `free-gpt-image-2-edit` | генерация и правка на OdiRouter (бесплатные каналы) |
| `IMGGEN_POLL_MODEL` | — | модель для Pollinations (по умолчанию их дефолт); `IMGGEN_POLLINATIONS=off` убирает канал из цепочки |
| `INTENT_HEADS` | `off` — не переставлять голову пула на math/code |
| `MATH_HEADS` / `CODE_HEADS` | по умолчанию `deepseek-v4-flash,deepseek-v4-pro` | кому отвечать первым на арифметике и коде |
| `MODELS_PER_SOURCE` | сколько строк брать у одного провайдера (200) — иначе говорливый агрегатор вытеснит остальных |
| `MODELS_REFRESH_MS` | `1800000` | возраст каталога моделей, после которого он обновляется |

Проверки: `node test/limits.test.js` (43) — там же «второй изолятор видит
наказание», «хранилище упало — ответ живёт», «обе формы значения читаются»,
`A6`–`A6c` в `test/memory.test.js` держат форму ключей.

## ☁️ Деплой (Cloudflare Pages)

Хостинг — **Cloudflare Pages**. Прод: `https://metiger-ai.pages.dev`.

Git-интеграции у проекта **нет**: `git push` ничего не публикует, прод обновляется
только загрузкой сборки. Для этого есть один скрипт — он делает всё сразу:

```bash
npm run publish                 # тесты → сборка → прод → проверка прода
npm run publish -- --bump       # + поднять APP_VERSION на 0.001
npm run publish -- --commit "что изменили"   # сначала коммит и пуш в main
npm run publish -- --fast       # пропустить тесты (если они только что шли)
npm run publish -- --preview    # залить на preview-адрес, прод не трогать
npm run publish -- --dry        # показать, что будет сделано
```

Доступы берутся из окружения, иначе из `keys/.secrets.env` (папка `keys/` целиком в
`.gitignore` — значения в репозиторий не попадают и наружу не печатаются). GitHub Actions (`ci.yml`)
дополнительно проверяет сборку на каждый push — но публикует всё равно скрипт.

Четыре грабли, из-за которых скрипт и существует:

1. деплой **без** `--branch main` уходит в preview, и прод остаётся на старом
   билде — выглядит как «я выложил, а изменений нет»;
2. `wrangler@latest` требует Node ≥ 22, рабочая ветка — `wrangler@3`;
3. секреты Pages нельзя записать прямым запросом к API (`405`), только
   `wrangler pages secret put`;
4. деплой из другого каталога теряет `functions/` — вместе с `/api/chat` и
   `/telegram/webhook`; скрипт сам делает `cd` в корень репозитория.

## 🔑 Ключи и переменные

**Ключи.** В репозитории их нет ни в одном файле — только имена переменных. Всё, что
настоящее, лежит в одной папке `keys/` (она в `.gitignore` целиком): `keys/.dev.vars` —
ключи моделей (формат Cloudflare, `ИМЯ=значение`, несколько ключей через запятую),
`keys/.secrets.env` — доступы Cloudflare/Telegram/GitHub для скриптов,
`keys/КЛЮЧИ_И_МОДЕЛИ.md` — снимок того, кто чем платит (тоже вне git).

На проде ключи живут не в файле, а в секретах Pages: `wrangler pages secret put GROQ_KEYS --project-name metiger-ai`
