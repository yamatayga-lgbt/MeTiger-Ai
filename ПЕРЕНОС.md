# Перенос движка из Yama AI в MeTiger Ai

Идея: не переписывать «с нуля», а переносить проверенные контуры **по одному этапу**,
чтобы каждый шаг можно было потрогать живьём, а не получить большой слой кода, который
«где-то там должен работать».

Движок Yama на момент переноса: `1.0.227` в проде + недопушенный `1.0.228`
(совет зрячих голов и локальная голова) — локальный коммит `bd36f53`, на Render не уезжал.

## Что уже перенесено — Этап 1 «голос»

| Было в Yama | Стало в MeTiger | Что это даёт |
|---|---|---|
| `llm.js` (2495 строк: провайдеры, ключи, ротация, квоты, паузы) | `engine/providers.js` | Таблица 12 бесплатных провайдеров снята с живого движка (не с памяти): `label/kind/base/limit/models`, паузы под тариф (`odirouter` 4000 мс и др.), лимиты (OpenRouter 50/сутки). `buildTable(env)` читает окружение на каждый запрос — в Worker нет `process.env`. |
| `llm.js::callProvider` | `engine/shape.js` | Форма запроса каждого провайдера: openai-совместимые (`/chat/completions`, картинки — `image_url`), Gemini (`:generateContent`, system — user-turn с подтверждением, картинки — `inline_data`), Cloudflare (`{acc}` в пути). Разбор: `reasoning_content` отдельно, think-теги вырезаются, блок по безопасности ≠ пустой ответ. |
| `models.js::classifyTask` + пулы | `engine/route.js` | Классификатор перенесён **вместе с порядком проверок** («сравни postgres и mysql» → reasoning, а не code, хотя `sql` в тексте есть; «почему этот код не работает» → code). Зрение по примете имени + белый список «в имени всё есть, а зрения нет». |
| `engine.js::run/chat` + обход | `engine/chat.js` | Обход провайдеров: ротация по самому разгруженному ключу, 429 → cooling ключа, 401/403 → ключ мёртв, 402/баланс → сутки, «ответ-ошибка» и «вежливый отказ» ≠ ответ, обрыв на `finish_reason=length` допиливается, список `tried` остаётся видимым. |
| `server.js` (`/api/chat`) | `functions/api/chat.js` | Pages Function: `POST /api/chat` (текст, история, картинки) + `GET` = кто жив. CORS открыт, лимитер 12 запросов/мин на ip, без ключей — 503 со списком попыток, а не пустой ответ. |
| — | `scripts/api-dev.js` | Тот же обработчик в Node: `npm run api` → `http://127.0.0.1:8788/api/chat`. Dev и прод исполняют один код. |
| `src/lib/mock.ts::generateReply` | `src/lib/api.ts` + `src/App.tsx` | Фронт зовёт движок. Моки остались только как фолбэк режима разработки; в проде при недоступности показывается причина, а не красивая заглушка. |

Не переносилось осознанно: `express`, `fs`, GitHub-persist — на Cloudflare их нет, см. «архитектура».

## Проверки (что реально прогонялось)

```
node test/route.test.js  → 34 пройдено, 0 провалено   # классификатор, очереди, форма запроса, разбор ответа
node test/chat.test.js   → 28 пройдено, 0 провалено   # обход, 429, ротация ключей, лимиты, /api/chat
npx tsc --noEmit         → чисто
npm run build            → собралось (192.76 kB JS, gzip 60.41 kB)
```

Живой прогон через `npm run api` + ключи бесплатных провайдеров (3 запроса, бережём 5 RPM):

| Запрос | Итог |
|---|---|
| «привет, ты кто» | `ok`, groq/`allam-2-7b`, intent `fast`, 593 мс |
| «24 яблока, треть съели утром, вечером ещё 5» | **`11`** — тот же верный ответ, что давал Yama с ансамблем; groq/`openai/gpt-oss-120b`, intent `reasoning`, tier `smart`, 561 мс |
| «напиши функцию js: сумма цифр числа» | рабочий код, intent `code`, 771 мс, 0 повторных попыток |

Что при этом **не** так и известно: ответы несут самоцензуру модели («как модель я не могу…») —
это чинится Этапом 2 (слои `freedom`/`style`), а не промптом. И очередь моделей статична:
в Yama она улучшалась живыми оценками (`braveScore`) — перенос на Этапе 4.

## Что НЕ переносится на Cloudflare и почему

- `sandbox.js` (`node:vm`) и `tdd.js`/`core.js` (прогон кода из ответа) — в Worker **нет** `vm`
  и `child_process`. Песочница требует Node-рантайма. Варианты: (а) оставить тяжёлые контуры
  на Node-сервисе и звать его из воркера; (б) `Workerd`/контейнер; (в) отказаться от прогона.
  Решение принимается на Этапе 4, не раньше.
- `memory.js` на файловой системе → KV/D1 (Этап 3).
- Живой реестр OpenRouter (`discover()` + кэш на диск) → реестра на диске нет; либо KV-кэш,
  либо статические списки (сейчас — статика).

## План этапов

1. ✅ **Голос** — движок ответа + вход `/api/chat` + фронт вместо имитации.
2. **Слои над моделью** — `ensemble.js` (голоса на IQ/математике) и `vcouncil.js` (совет зрячих
   голов на фактах по картинке). Чистый JS, переносится как есть, сети не требует в тестах.
3. **Память и подстройка** — `memory.js` → KV/D1, `attune.js` (профиль человека), `style.js`,
   тон; плюс `freedom.js` против «как языковая модель я не…».
4. **Оценки и роутинг по фактам** — `braveScore`-подобный учёт «кто реально отвечал прямо»,
   `router-bench`, `model-shootout` (с корпусом и мерой), локальный слот `local` под Ollama.
5. **Тяжёлые контуры** — решение по песочнице (Node-рантайм рядом с воркером) и `tdd.js`.
6. **Бот** — webhook на воркер: `/start`, `/help`, `initData` валидация (`WEBAPP_SECRET`),
   кнопка «Открыть MeTiger Ai» уже настроена на стороне BotFather.
7. **Данные Yama** — профиль, уроки, накопленная память, usage → перенос в KV/D1.

## Ключи и секреты (как заведено сейчас)

Локально: `.dev.vars` (в `.gitignore`, в git не попадает, содержит только `*_KEYS` и
`CLOUDFLARE_ACCOUNT_ID`). Прод: `wrangler pages secret put GROQ_KEYS --project-name metiger-ai`.
В коде ключей нет ни в одном файле — в репозитории только имена переменных.

⚠️ Токены (Telegram, GitHub PAT, Cloudflare API) светились в переписке текстом — их надо
перевыпустить независимо от того, как настроены секреты.
